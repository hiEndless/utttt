## 🔄 数据流向图

### 1. 数据采集流程

```
Binance Exchange
      │
      ├─── REST API ────► REST服务 ────► Redis (K线、指标)
      │
      └─── WebSocket ────► WS服务 ────► Redis (实时价格、深度)
```

### 2. 事件生成流程

```
Redis (K线、指标)
      │
      ▼
事件中心 (Event Center)
      │
      ├─── 指标检测 ────► L0处理器 ────► raw_event_stream
      │
      ├─── 事件聚合 ────► L1聚合器 ────► l0_events, l1_events
      │
      └─── 事件评分 ────► 最终评分器 ────► final_events
```

### 3. AI分析流程

```
final_events (或直接指标数据)
      │
      ▼
AI分析服务 (run_ai_analysis.py)
      │
      ├─── 模式1: 事件流分析 ────► 读取事件流 ────► 单事件分析
      │
      └─── 模式2: 直接分析 ────► 多时间维度分析器 ────► 并发分析
            │
            ├─── 1m 分析 (并发)
            ├─── 5m 分析 (并发)
            ├─── 15m 分析 (并发)
            └─── 1h 分析 (并发)
                  │
                  ▼
            整合分析结果
                  │
                  ▼
            获取市场数据 (多空比、爆仓、支撑阻力位)
                  │
                  ▼
            最终决策
```

## 🎯 Agent专家系统详解

### Agent类型

| Agent | 职责 | 输入 | 输出 |
|-------|------|------|------|
| **Technical** | 技术分析 | K线数据、技术指标 | 技术分析结果、买卖信号 |
| **Risk** | 风险评估 | 市场数据、持仓信息 | 风险等级、风险建议 |
| **News** | 新闻分析 | 新闻数据、市场情绪 | 市场情绪、影响评估 |
| **Portfolio** | 投资组合 | 持仓信息、市场数据 | 仓位建议、配置建议 |
| **Trading Decision** | 交易决策 | 所有Agent分析结果 | 最终交易决策 (open/close/hold) |

### Agent协作模式

#### 1. Default模式 (默认)
```
Technical → Risk → News
    │         │      │
    └─────────┴──────┘
           │
           ▼
      Reflection
           │
           ▼
    Trading Decision
```

#### 2. Debate模式 (辩论)
```
Technical ←→ Risk ←→ News
    │         │      │
    └─────────┴──────┘
           │
           ▼
      Reflection
           │
           ▼
    Trading Decision
```

#### 3. Delphi模式 (德尔菲)
```
Technical → Risk → News
    │         │      │
    └─────────┴──────┘
           │
           ▼
      Reflection (多轮)
           │
           ▼
    Trading Decision
```

#### 4. N-Variant模式 (多变量)
```
Technical (变体1) ──┐
Technical (变体2) ──┤
Technical (变体3) ──┼──► 综合
Risk (变体1) ───────┤
Risk (变体2) ───────┘
           │
           ▼
    Trading Decision
```

## 🔧 关键组件说明

### 1. 数据采集层

#### REST服务 (`run_rest.py`)
- **功能**: 定期抓取历史K线数据
- **频率**: 定时任务（如每1分钟）
- **数据**: K线、技术指标、持仓比例

#### WebSocket服务 (`run_ws.py`)
- **功能**: 实时监控价格和订单簿
- **数据**: 实时价格、订单簿深度、爆仓数据
- **特点**: 低延迟、实时推送

### 2. 事件处理层

#### 事件中心 (`run_event_center.py`)
- **L0处理器**: 检测技术指标异常，生成原始事件
- **L1聚合器**: 聚合相关事件，提升事件级别
- **最终评分器**: 评估事件重要性，筛选重要事件

### 3. AI分析层

#### 多时间维度分析器 (`MultiTimeframeAnalyzer`)
- **功能**: 并发分析多个时间维度（1m, 5m, 15m, 1h）
- **特点**: 
  - 并发执行，提高效率
  - 超时控制，防止阻塞
  - 市场数据整合

#### 团队编排器 (`TeamOrchestrator`)
- **功能**: 协调多个Agent协作
- **模式**: default, debate, delphi, n_variant
- **流程**: 分析 → 反思 → 融合 → 决策

### 4. 交易执行层

#### 交易执行器 (`TradingExecutor`)
- **功能**: 执行交易决策
- **流程**: 验证 → 生成JSON → 推送到队列

## 🚀 完整执行流程示例

### 场景: 直接分析模式 (--direct)

```
1. 用户执行命令
   python run_ai_analysis.py --direct --symbol BTCUSDT
   
2. AI分析服务启动
   ├─── 连接Redis
   └─── 初始化多时间维度分析器
   
3. 获取指标数据
   ├─── 1m 指标 (并发)
   ├─── 5m 指标 (并发)
   ├─── 15m 指标 (并发)
   └─── 1h 指标 (并发)
   
4. 并发分析各时间维度
   ├─── 1m: Technical + Risk → 结果1
   ├─── 5m: Technical + Risk → 结果2
   ├─── 15m: Technical + Risk → 结果3
   └─── 1h: Technical + Risk → 结果4
   
5. 整合分析结果
   └─── analysis_by_timeframe = {
         "1m": 结果1,
         "5m": 结果2,
         "15m": 结果3,
         "1h": 结果4
       }
   
6. 获取市场数据
   ├─── 当前价格
   ├─── 多空比
   ├─── 爆仓数据
   └─── 支撑阻力位
   
7. 最终决策
   └─── Trading Decision Agent
        ├─── 综合分析所有时间维度
        ├─── 结合市场数据
        └─── 生成决策: {action, symbol, ...}
   
8. 交易执行
   └─── 推送到 Redis: TASK_ADD_TRADE
```
