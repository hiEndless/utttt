## 标准错误码定义

系统中定义的标准错误码位于 `status_codes.py` 文件中，通过 `StatusCode` 枚举类统一管理。每个错误码包含数字值和对应的中文消息，用于标准化API响应和错误提示。

| 错误码名称 | 数字值 | 中文消息 | 触发场景 |
|-----------|--------|----------|----------|
| SUCCESS | 0 | 请求成功 | API请求正常完成 |
| ERROR | 1 | 请求失败 | 通用请求失败，未明确分类的错误 |
| PARAM_ERROR | 1001 | 参数错误 | 客户端请求参数格式或类型不正确 |
| NOT_FOUND | 1002 | 资源未找到 | 请求的资源不存在（如用户、订单等） |
| SERVER_ERROR | 1003 | 服务器内部错误 | 服务端未预期的异常或崩溃 |
| VALIDATION_ERROR | 1004 | 数据验证错误 | 业务逻辑校验失败（如金额超限） |
| DATABASE_ERROR | 1005 | 数据库操作错误 | 数据库连接失败、查询异常或事务错误 |

通过 `StatusCode.get_message(code)` 方法可获取对应错误码的中文提示消息，便于前端统一展示用户友好的错误信息。

## 事件等级配置体系

事件等级体系在 `event_levels.yml` 文件中定义，用于评估市场事件的严重程度。体系包含多种事件类型，每种类型通过多个指标（metrics）进行评估，并设定阈值和聚合策略。

### 事件类型与指标配置

#### force_spike_sell / force_spike_buy
- **指标**：`delta_sell_qty`, `delta_sell`（卖出突增）或 `delta_buy_qty`, `delta_buy`（买入突增）
- **方法**：百分位统计（pctl）
- **阈值**：
  - p80: 2
  - p90: 3
  - p95: 4
  - p99: 5
- **聚合策略**：`max`（取各指标中最高等级）

#### force_intensity
- **指标**：`intensity`（市场强度）
- **方法**：百分位统计
- **阈值**：同上
- **聚合策略**：`max`

#### force_sell_dominance / force_buy_dominance
- **指标**：
  - `dominance_sell_ratio` / `dominance_buy_ratio`：买卖主导比率
  - `delta_sell_qty` / `delta_buy_qty`：突增量
- **方法**：
  - 比率使用绝对值（absolute）
  - 突增量使用百分位（pctl）
- **阈值**：
  - 比率：base: 2.0, x1_5: 1.5, x2_5: 2.5
  - 突增量：p80: 3, p90: 4, p95: 5, p99: 5
- **聚合策略**：`max`

## 事件等级评分机制

事件等级通过多维度指标计算综合得分，并映射为最终等级。评分流程如下：

1. **指标评分**：根据 `pctl` 或 `absolute` 方法计算各指标得分
2. **阈值匹配**：将指标值与预设阈值比较，确定初步等级
3. **聚合策略**：使用 `combine: max` 策略，取所有指标中的最高等级作为事件等级
4. **最终分类**：根据总分映射为事件级别

在 `event.py` 中定义了事件分类函数：

```python
def classify_event(total_score: float) -> int:
    abs_score = abs(total_score)
    if abs_score < 2:
        return 1  # raw
    if abs_score < 4:
        return 2  # l0
    if abs_score < 7:
        return 3  # l1
    return 4      # final
```

该函数将事件分为四个等级：
- **1级 (raw)**：初步检测，低置信度
- **2级 (l0)**：初步确认，中等置信度
- **3级 (l1)**：高度确认，高置信度
- **4级 (final)**：最终确认，最高置信度

## 前端颜色标识映射

事件等级在前端通过颜色标识进行可视化展示，便于用户快速识别事件严重性。颜色映射基于事件优先级字段。

在 `read_final_stream.py` 中定义了优先级到权重的映射：

```python
def _weight(priority: str) -> int:
    m = {"low": 10, "medium": 50, "high": 80, "critical": 100}
    return m.get(priority or "low", 0)
```

对应的颜色标识如下：
- **low (低)**：绿色或蓝色，表示普通事件
- **medium (中)**：黄色，表示需要注意的事件
- **high (高)**：橙色，表示重要事件
- **critical (严重)**：红色，表示紧急或高影响事件

此映射确保高优先级事件在前端界面中以醒目的红色突出显示，帮助用户快速响应关键市场变化。

## 错误处理与调试建议

### 开发者调试建议
1. **参数错误 (PARAM_ERROR)**：
   - 检查请求参数类型、格式和必填字段
   - 使用日志输出接收到的原始参数进行比对

2. **资源未找到 (NOT_FOUND)**：
   - 验证资源ID是否存在
   - 检查数据库查询逻辑和过滤条件

3. **数据库错误 (DATABASE_ERROR)**：
   - 查看数据库连接状态和配置
   - 检查SQL语句执行情况和事务完整性

4. **服务器内部错误 (SERVER_ERROR)**：
   - 查阅服务端日志定位异常堆栈
   - 验证依赖服务（如Redis、数据库）的可用性

### 用户提示建议
- 对 `SUCCESS` 和 `ERROR` 提供简洁明了的结果反馈
- 对 `PARAM_ERROR` 给出具体参数错误说明
- 对 `NOT_FOUND` 使用友好提示如“您查找的资源可能已被删除”
- 对 `SERVER_ERROR` 建议稍后重试并记录问题

通过统一的错误码体系，可实现前后端一致的错误处理逻辑，提升系统可维护性和用户体验。
