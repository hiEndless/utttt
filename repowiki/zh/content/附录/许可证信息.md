## 许可证文本获取方式

各开源库的许可证文本可通过以下方式获取：

- **PyPI 包内文件**：大多数库的许可证文件位于 Python 虚拟环境的 `site-packages` 目录下，路径如 `venv/lib/python3.11/site-packages/<package_name>.dist-info/LICENSE`。
- **官方 GitHub 仓库**：访问各库的 GitHub 主页，通常在根目录下有 `LICENSE` 或 `COPYING` 文件。
  - FastAPI: https://github.com/tiangolo/fastapi
  - Pydantic: https://github.com/pydantic/pydantic
  - APScheduler: https://github.com/agronholm/apscheduler
  - aiohttp: https://github.com/aio-libs/aiohttp
  - redis-py: https://github.com/redis/redis-py
  - lxml: https://github.com/lxml/lxml
  - numpy: https://github.com/numpy/numpy
  - PyJWT: https://github.com/jpadilla/pyjwt

## 二次开发与商业部署合规提醒

在进行二次开发或商业部署时，请务必遵守以下开源协议要求：

1. **保留版权声明**：在分发软件时，必须在文档或关于页面中包含所有依赖库的版权声明。
2. **提供许可证副本**：建议在项目发布时附带一个 `THIRD_PARTY_LICENSES.txt` 文件，汇总所有依赖库的许可证文本。
3. **注意 Apache-2.0 的 NOTICE 要求**：若使用了 `aiohttp` 等 Apache-2.0 许可的库，需在 NOTICE 文件中说明其使用。
4. **避免品牌推广限制**：对于 `numpy` 等采用 BSD-3-Clause 的库，不得使用其项目名称或贡献者名字为您的产品做背书。
5. **专利条款理解**：Apache-2.0 许可证提供了明确的专利授权，降低了专利诉讼风险，但仍需注意贡献者专利条款的适用范围。

忽视这些要求可能导致法律风险，包括但不限于侵权诉讼和被迫开源。
