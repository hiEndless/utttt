## 简介
UTaker系统是一个基于事件驱动的量化分析平台，包含数据采集、事件处理、智能代理和API服务等多个组件。本部署与运维文档旨在提供从零搭建UTaker系统的完整操作指南，涵盖服务启动顺序、部署方案、配置要求、监控建议及故障排查等内容。

## 服务启动顺序
为确保系统稳定运行，必须严格按照以下顺序启动服务：

1. **启动Redis**：作为整个系统的核心消息中间件和状态存储，Redis必须首先启动。
2. **启动data_server**：负责从Binance等交易所采集市场数据，包括K线、资金费率、持仓量等。
3. **启动event_center**：处理原始事件流，生成指标事件并进行分级聚合。
4. **启动agent_server**：基于事件进行智能分析，执行信号验证、风险评估等高级逻辑。
5. **启动api服务**：对外提供RESTful接口，供前端或其他客户端调用。

## 部署方案
UTaker系统支持多种部署方式，推荐使用Docker容器化部署或Supervisor进程管理。

### Docker部署方案
使用Docker Compose进行服务编排，示例如下：

```yaml
version: '3.8'
services:
  redis:
    image: redis:7-alpine
    container_name: utaker-redis
    command: redis-server --save 60 1 --appendonly yes --stream-node-max-bytes 4096kb
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data

  data_server:
    build: ./data_server/binance/rest_binance
    container_name: utaker-data-server
    environment:
      - REDIS_HOST=redis
      - REDIS_PORT=6379
    depends_on:
      - redis

  event_center:
    build: ./event_center
    container_name: utaker-event-center
    environment:
      - REDIS_HOST=redis
      - REDIS_PORT=6379
    depends_on:
      - redis

  agent_server:
    build: ./agent_server
    container_name: utaker-agent-server
    environment:
      - REDIS_HOST=redis
      - REDIS_PORT=6379
    depends_on:
      - redis

  api:
    build: ./api
    container_name: utaker-api
    ports:
      - "8000:8000"
    environment:
      - REDIS_HOST=redis
      - REDIS_PORT=6379
      - APP_HOST=0.0.0.0
      - APP_PORT=8000
    depends_on:
      - redis

volumes:
  redis_data:
```

## 各服务启动命令与参数
### data_server启动命令
```bash
python data_server/binance/rest_binance/app/main.py
```
环境变量：
- `REDIS_HOST`: Redis服务器地址，默认为`127.0.0.1`
- `REDIS_PORT`: Redis端口，默认为`6379`
- `REDIS_PASSWORD`: Redis密码（可选）
- `REDIS_DB`: Redis数据库编号，默认为`1`

### event_center启动命令
```bash
python event_center/main.py
```
环境变量：
- `REDIS_HOST`: Redis服务器地址
- `REDIS_PORT`: Redis端口
- `REDIS_PASSWORD`: Redis密码
- `REDIS_DB`: Redis数据库编号
- `RAW_STREAM`: 原始事件流名称，默认为`raw_event_stream`
- `L0_STREAM`: L0事件流名称，默认为`l0_events`
- `L1_STREAM`: L1事件流名称，默认为`l1_events`
- `FINAL_STREAM`: 最终事件流名称，默认为`final_events`

### agent_server启动命令
```bash
python agent_server/main.py
```
环境变量：
- `REDIS_HOST`: Redis服务器地址
- `REDIS_PORT`: Redis端口
- `REDIS_PASSWORD`: Redis密码
- `REDIS_BD`: Redis数据库编号（注意：此处为`BD`而非`DB`）
- `API_BASE_URL`: API基础URL，默认为`http://localhost:9931/api`
- `LOG_LEVEL`: 日志级别，默认为`INFO`

### api服务启动命令
```bash
python api/main.py
```
环境变量：
- `REDIS_HOST`: Redis服务器地址
- `REDIS_PORT`: Redis端口
- `APP_HOST`: API服务监听地址，默认为`0.0.0.0`
- `APP_PORT`: API服务端口，默认为`8000`
- `APP_DEBUG`: 是否启用调试模式

## Redis配置要求
Redis是UTaker系统的核心组件，其配置直接影响系统性能和稳定性。

### 内存配置
- 建议分配至少4GB内存，具体大小取决于监控的交易对数量和数据保留时间
- 启用内存淘汰策略：`maxmemory-policy allkeys-lru`
- 设置最大内存限制：`maxmemory 4gb`

### 持久化配置
- 启用AOF持久化：`appendonly yes`
- AOF同步策略：`appendfsync everysec`
- 定期RDB快照：`save 60 1`（每60秒至少1个键改变时触发）

### Stream设置
- 设置Stream节点最大字节数：`stream-node-max-bytes 4096kb`
- 限制Stream长度，防止无限增长：
  - 原始事件流：`XTRIM raw_event_stream MAXLEN ~ 10000`
  - L0事件流：`XTRIM l0_events MAXLEN ~ 5000`
  - L1事件流：`XTRIM l1_events MAXLEN ~ 2000`
  - 最终事件流：`XTRIM final_events MAXLEN ~ 1000`

### 其他重要配置
- 最大连接数：`maxclients 10000`
- TCP keepalive：`tcp-keepalive 300`
- 禁用保护模式：`protected-mode no`（生产环境需配合防火墙）

## 常见故障排查
### 数据采集中断
**现象**：data_server停止采集新数据，Redis中无新K线数据更新。

**排查步骤**：
1. 检查data_server进程是否正常运行
2. 查看data_server日志是否有网络连接错误
3. 验证Binance API是否正常（可访问`https://api.binance.com/api/v3/ping`）
4. 检查Redis连接是否正常
5. 确认`symbol:binance`集合中是否有需要监控的交易对

### 事件堆积
**现象**：Redis中事件Stream长度持续增长，event_center处理速度跟不上。

**排查步骤**：
1. 检查event_center进程是否正常运行
2. 查看event_center日志是否有异常
3. 使用`XLEN`命令检查各Stream长度
4. 监控event_center的CPU和内存使用率
5. 考虑增加event_center实例或优化事件处理逻辑

### 代理无响应
**现象**：agent_server进程运行但无输出，或处理延迟极高。

**排查步骤**：
1. 检查agent_server日志是否有异常
2. 验证与Redis的连接是否正常
3. 检查API服务是否可访问
4. 监控agent_server的资源使用情况
5. 确认事件流中是否有新事件进入

## 性能优化建议
### 调整采集频率
根据实际需求调整data_server的采集频率，避免不必要的资源消耗：

```python
# 在 data_server/binance/rest_binance/app/config.py 中调整
rate_limits_seconds: dict = {
    '1m': 60,    # 1分钟K线每60秒采集一次
    '5m': 300,   # 5分钟K线每300秒采集一次
    '1h': 1800,  # 1小时K线每1800秒采集一次
    '1d': 43200, # 1天K线每43200秒采集一次
}
```

### 优化指标计算算法
在`event_center/indicators_event/engine/event_engine.py`中优化事件引擎：

1. 使用缓存避免重复计算
2. 并行处理多个交易对的指标
3. 优化时间序列数据的存储和查询

### 增加消费者实例
对于高负载场景，可增加各服务的实例数量：

- 部署多个data_server实例，分担数据采集压力
- 部署多个event_center实例，提高事件处理能力
- 部署多个agent_server实例，提升智能分析吞吐量

### Redis性能优化
1. 使用Redis集群模式分散负载
2. 为不同类型的Stream设置不同的过期策略
3. 定期执行`MEMORY PURGE`清理内存碎片
4. 使用Pipeline批量操作减少网络往返

### 异步处理优化
充分利用异步特性，提高系统吞吐量：

```python
# 在 event_center/main.py 中，并发处理多个交易所
tasks = []
for ex in exchanges:
    tasks.extend([
        asyncio.create_task(ac_ex.run()),
        asyncio.create_task(fsc_ex.run()),
        asyncio.create_task(ind_event_run_loop(ex, poll_sec=poll, concurrency=conc)),
    ])
```
