## 日志管理

UTaker系统的日志管理基于Python标准logging模块实现，各服务通过配置文件统一管理日志级别和输出格式。系统未明确指定日志文件路径，日志默认输出到标准输出（stdout），可通过重定向或容器化部署时的日志收集机制进行持久化存储。

各服务的日志级别可通过环境变量进行配置，所有服务默认日志级别为"INFO"。日志输出包含服务标识、时间戳、日志级别和具体消息，便于运维人员快速识别和定位问题。

## 关键监控指标

### data_server数据采集监控

data_server负责从Binance交易所采集市场数据，其核心监控指标包括数据采集频率与延迟。采集频率由`rate_limits_seconds`配置项控制，不同时间周期的K线数据有不同的采集间隔：

- 1分钟K线：每60秒采集一次
- 5分钟K线：每150秒采集一次
- 30分钟K线：每600秒采集一次
- 1小时K线：每900秒采集一次
- 2小时K线：每1800秒采集一次
- 4小时K线：每3600秒采集一次
- 1天K线：每43200秒（12小时）采集一次

采集延迟可通过监控`task_trigger`日志中的时间戳与当前时间的差值来评估，确保数据采集的及时性。

### event_center事件吞吐量监控

event_center采用三级事件处理流水线（L0→L1→Final），其事件吞吐量是系统健康状况的关键指标。

**L0处理器**：从`raw_event_stream`读取原始事件，进行初步过滤和确认，输出到`l0_events`流。L0处理的关键指标包括：
- 原始事件输入速率
- L0确认事件输出速率
- 窗口内信号一致性比率

**L1聚合器**：从`l0_events`流读取L0事件，按交易对和时间框架进行聚合，输出到`l1_events`流。L1处理的关键指标包括：
- L0事件输入速率
- L1聚合事件输出速率
- 各时间框架（短、中、长）的分数聚合情况

**Final分级器**：从`l1_events`流读取L1事件，进行最终状态确认和去抖动处理，输出到`final_events`流。Final处理的关键指标包括：
- L1事件输入速率
- Final事件输出速率
- 市场状态变化频率

### agent_server代理响应时间监控

agent_server通过监听`final_events`流获取最终市场状态，其响应时间是系统整体延迟的关键指标。响应时间包括：
- 从`final_events`流读取事件的延迟
- 代理决策和执行的处理时间
- 与外部API交互的网络延迟

可通过监控`final_events`流中事件的时间戳与代理处理完成时间的差值来评估代理响应时间。

### Redis监控指标

Redis作为UTaker系统的核心消息中间件和状态存储，其性能直接影响整个系统的稳定性。关键Redis监控指标包括：

**内存使用率**：监控Redis实例的内存使用情况，确保不超过物理内存限制，避免因内存不足导致的性能下降或服务中断。

**Stream积压长度**：监控各事件流的消费者组待处理消息数量，反映事件处理的实时性。关键流的积压情况包括：
- `raw_event_stream`：原始事件积压长度
- `l0_events`：L0事件积压长度
- `l1_events`：L1事件积压长度
- `final_events`：最终事件积压长度

积压长度持续增长表明下游处理能力不足，需要优化处理逻辑或增加资源。

## Prometheus/Grafana集成建议

为实现UTaker系统的全面监控，建议集成Prometheus和Grafana构建监控平台。以下是具体的集成建议：

### 自定义监控脚本示例

创建一个Python脚本，定期从Redis获取关键指标并暴露给Prometheus：

```python
# metrics_exporter.py (概念代码，非实际文件)
from prometheus_client import start_http_server, Gauge
import asyncio
import aioredis

# 定义Prometheus指标
RAW_STREAM_BACKLOG = Gauge('utaker_raw_stream_backlog', 'Raw event stream backlog length')
L0_STREAM_BACKLOG = Gauge('utaker_l0_stream_backlog', 'L0 event stream backlog length')
L1_STREAM_BACKLOG = Gauge('utaker_l1_stream_backlog', 'L1 event stream backlog length')
FINAL_STREAM_BACKLOG = Gauge('utaker_final_stream_backlog', 'Final event stream backlog length')
REDIS_MEMORY_USAGE = Gauge('utaker_redis_memory_usage', 'Redis memory usage in bytes')

async def collect_metrics():
    redis = aioredis.from_url("redis://localhost:6379")
    while True:
        # 获取Stream积压长度
        raw_backlog = await redis.xlen("raw_event_stream")
        l0_backlog = await redis.xlen("l0_events")
        l1_backlog = await redis.xlen("l1_events")
        final_backlog = await redis.xlen("final_events")
        
        # 获取Redis内存使用
        info = await redis.info("memory")
        memory_usage = info["used_memory"]
        
        # 更新Prometheus指标
        RAW_STREAM_BACKLOG.set(raw_backlog)
        L0_STREAM_BACKLOG.set(l0_backlog)
        L1_STREAM_BACKLOG.set(l1_backlog)
        FINAL_STREAM_BACKLOG.set(final_backlog)
        REDIS_MEMORY_USAGE.set(memory_usage)
        
        await asyncio.sleep(15)  # 每15秒收集一次

if __name__ == "__main__":
    start_http_server(8000)  # 在端口8000暴露指标
    asyncio.run(collect_metrics())
```

### Prometheus配置

在Prometheus配置文件中添加UTaker的监控目标：

```yaml
scrape_configs:
  - job_name: 'utaker'
    static_configs:
      - targets: ['localhost:8000']
```

## Redis监控与调试工具

为方便运维人员实时监控和调试UTaker系统的Redis状态，系统提供了多种工具和方法。

### Redis CLI工具

推荐使用`redis-cli --stat`命令实时观察Redis实例的整体状态：

```bash
redis-cli --stat
```

该命令提供实时更新的统计信息，包括：
- 连接数
- 命令处理速率
- 内存使用情况
- 网络流量
- Key空间统计

### 事件流调试工具

系统提供了专门的Python工具脚本，用于读取和分析事件流内容：

**read_l1_stream.py**：读取最新的L1事件，用于调试L1聚合器的输出。

```bash
python tools/read_l1_stream.py
```

**read_final_stream.py**：读取最新的Final事件，并进行结构化分析，用于验证最终市场状态的正确性。

```bash
python tools/read_final_stream.py
```

**publish_l1_test.py**：向L1流发布测试事件，用于验证L1到Final的处理逻辑。

```bash
python tools/publish_l1_test.py
```

这些工具可以帮助运维人员快速诊断事件处理流水线中的问题，确保系统按预期工作。

## 日志轮转策略

为防止日志文件无限增长导致磁盘溢出，建议实施日志轮转策略。虽然系统本身未实现日志轮转，但可以通过外部工具实现：

### 使用logrotate

在Linux系统上配置logrotate，定期轮转和压缩日志文件：

```bash
# /etc/logrotate.d/utaker
/var/log/utaker/*.log {
    daily
    missingok
    rotate 30
    compress
    delaycompress
    notifempty
    create 644 root root
    sharedscripts
    postrotate
        # 重启服务或发送信号以重新打开日志文件
        systemctl reload utaker
    endscript
}
```

### 容器化部署日志轮转

如果使用Docker部署，可以通过Docker的日志驱动配置日志轮转：

```yaml
# docker-compose.yml
services:
  utaker:
    image: utaker:latest
    logging:
      driver: "json-file"
      options:
        max-size: "10m"
        max-file: "10"
```

此配置将日志文件大小限制为10MB，最多保留10个历史文件，总日志大小不超过100MB。
