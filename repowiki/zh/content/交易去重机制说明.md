# 交易去重机制说明

## 当前实现情况

### 1. 冷却期设置

**当前值**：`cooldown_ttl = 10秒`

**作用**：防止短时间内重复处理相同交易对的L1事件

**位置**：`agent_server/trade_listen_main.py` 第55行

**说明**：
- 冷却期主要用于防止短时间内重复处理L1事件
- **不是用于交易去重**（交易去重由交易对去重机制实现）
- 10秒的冷却期可以防止同一个交易对在10秒内触发多次工作流

---

### 2. 交易对去重机制（核心机制）

**实现位置**：
- `agent_server/trade_listen_main.py` - `_is_position_open` 方法
- `agent_server/agent_workflow/components/executors/trade_decision_execution.py` - `_push_to_trade_queue` 方法

**Redis Key**：
- `trading:open_positions:binance` (Set) - 存储已开仓的交易对

**工作流程**：

1. **开仓时**：
   - 检查交易对是否已在 `trading:open_positions:binance` 中
   - 如果已存在，跳过（防止重复开仓）
   - 如果不存在，推送订单并记录到Redis

2. **平仓时**：
   - 从 `trading:open_positions:binance` 中移除交易对
   - 允许该交易对再次开仓

**代码实现**：
```python
# 开仓时记录
if order_type == 'open':
    await rc.sadd(position_key, symbol)
    trade_logger.info(f"记录开仓交易对: {symbol}")

# 平仓时清理
elif order_type == 'close':
    await rc.srem(position_key, symbol)
    trade_logger.info(f"清理平仓交易对: {symbol}")
```

---

### 3. 订单ID去重机制

**Redis Key**：
- `trading:orders:binance` (Set) - 存储订单ID

**作用**：防止同一订单重复推送

**订单ID格式**：`{symbol}_{timestamp}_{action}_{hash}`

---

## 多级去重检查流程

当前系统实现了**四级去重检查**：

```
1. 事件ID去重（_passes_dedup）
   └─> 5分钟内不重复处理相同 event_id
   
2. 冷却期检查（_passes_cooldown）
   └─> 10秒内不重复处理相同 symbol 的事件
   
3. 交易对去重（_is_position_open）⭐ 核心机制
   └─> 检查交易对是否已开仓（一次交易完成前不能第二次交易）
   
4. 订单ID去重（_push_to_trade_queue）
   └─> 检查订单ID是否已存在
```

## 当前机制是否符合需求

### 你的需求：一次交易完成之前，不能进行第二次交易

**当前实现**：✅ **已实现**

**实现方式**：
1. 开仓时记录交易对到Redis
2. 后续L1事件触发时，检查交易对是否已开仓
3. 如果已开仓，跳过处理（不触发工作流）
4. 平仓时自动清理，允许再次开仓

**效果**：
- ✅ 一次交易完成前，不能进行第二次交易
- ✅ 平仓后可以再次开仓
- ✅ 自动清理，无需手动操作

## 注意事项

1. **冷却期 vs 交易对去重**：
   - 冷却期：防止短时间内重复处理事件（10秒）
   - 交易对去重：防止重复开仓（直到平仓）

2. **平仓清理**：
   - 已实现平仓时自动清理
   - 如果平仓失败或异常，可能需要手动清理

3. **手动清理**（如需要）：
   ```bash
   # 清理某个交易对
   redis-cli SREM trading:open_positions:binance BTCUSDT
   
   # 清理所有交易对
   redis-cli DEL trading:open_positions:binance
   ```
