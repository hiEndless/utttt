## 服务启动顺序

### 第一步：启动Redis（必须）

```bash
# 确保Redis服务运行
redis-server --port 6379

# 或使用Docker
docker run -d -p 6379:6379 redis:latest
```

**验证**：
```bash
redis-cli ping
# 应该返回: PONG
```

---

### 第二步：启动数据采集服务

#### 2.1 启动REST API数据采集（K线数据）

```bash
# 在项目根目录
cd data_server/binance/rest_binance/app
python main.py
```

**功能**：采集K线、技术指标数据

**验证**：查看日志，应该看到定期采集K线数据

---

#### 2.2 启动WebSocket市场数据监听（价格缓存）

```bash

python -m data_server.binance.ws_binance.market_ws
```

**功能**：
- 实时接收市场数据（aggTrade、depth）

**验证**：
- 查看日志，应该看到"新增订阅"信息

---

#### 2.3 启动WebSocket用户数据监听（仓位快照）


- 检测仓位变化并清理已平仓记录

**验证**：
- 查看日志，应该看到"持仓:"信息
- 查看日志，应该看到"仓位快照完成"信息（每5分钟）

### 第六步：启动实时仓位监控服务（可选）

创建一个启动脚本 `start_position_monitor.py`：

```python
import asyncio
import logging
from agent_server.utils.position_monitor import PositionMonitor

logging.basicConfig(level=logging.INFO)

async def main():
    # 创建监控服务，每60秒检查一次
    monitor = PositionMonitor(check_interval=60)
    await monitor.start()
    
    try:
        # 保持运行
        print("仓位监控服务已启动，按Ctrl+C停止")
        await asyncio.sleep(3600 * 24)  # 运行24小时
    except KeyboardInterrupt:
        print("\n正在停止监控服务...")
    finally:
        await monitor.stop()
        print("监控服务已停止")

if __name__ == "__main__":
    asyncio.run(main())
```

**启动**：
```bash
python start_position_monitor.py
```

**功能**：
- 定期检查已开仓位的风险
- 识别止损/止盈机会
- 记录风险警告日志

**验证**：
- 查看日志，应该看到"仓位监控服务已启动"信息
- 查看日志，应该看到仓位风险检查信息（每60秒）

## 完整启动脚本

创建一个 `start_all_services.sh` 脚本（Linux/Mac）：

```bash
#!/bin/bash

# 启动所有服务（每个服务在独立的终端窗口）

# 1. Redis（确保已启动）
echo "检查Redis..."
redis-cli ping || echo "请先启动Redis: redis-server"

# 2. REST API数据采集
gnome-terminal --title="Data Server REST" -- bash -c "cd data_server/binance/rest_binance/app && python main.py; exec bash"

# 3. WebSocket市场数据
gnome-terminal --title="Market WS" -- bash -c "python -m data_server.binance.ws_binance.market_ws; exec bash"

# 4. WebSocket用户数据（需要设置环境变量）
if [ -z "$BINANCE_API_KEY" ] || [ -z "$BINANCE_API_SECRET" ]; then
    echo "警告: 未设置BINANCE_API_KEY和BINANCE_API_SECRET，跳过用户数据监听"
else
    gnome-terminal --title="User WS" -- bash -c "python -m data_server.binance.ws_binance.user_ws; exec bash"
fi

# 5. 事件中心
gnome-terminal --title="Event Center" -- bash -c "python -m event_center.main; exec bash"

# 6. Agent Server主服务
gnome-terminal --title="Agent Server" -- bash -c "python -m agent_server.main; exec bash"

# 7. 交易决策服务
gnome-terminal --title="Trade Decision" -- bash -c "python -m agent_server.trade_decision_main; exec bash"

# 8. API服务
gnome-terminal --title="API Server" -- bash -c "python -m api.main; exec bash"

# 9. 仓位监控服务（可选）
read -p "是否启动仓位监控服务? (y/n) " -n 1 -r
echo
if [[ $REPLY =~ ^[Yy]$ ]]; then
    gnome-terminal --title="Position Monitor" -- bash -c "python start_position_monitor.py; exec bash"
fi

echo "所有服务已启动！"
```

**Windows版本** `start_all_services.bat`：

## 测试优化功能

### 1. 测试交易去重机制

**步骤**：
1. 确保有交易对在监控列表中：`redis-cli SADD symbol:binance BTCUSDT`
2. 等待L1事件触发
3. 观察日志，应该看到：
   - "订单去重检查通过"
   - "记录开仓交易对: BTCUSDT"
4. 再次触发相同交易对的L1事件，应该看到：
   - "交易对已开仓，跳过"
   - "订单已存在，跳过"

**验证**：
```bash
# 查看已开仓交易对
redis-cli SMEMBERS trading:open_positions:binance

# 查看订单ID
redis-cli SMEMBERS trading:orders:binance
```

---

### 2. 测试价格缓存

**步骤**：
1. 启动WebSocket市场数据监听
2. 观察日志，应该看到价格更新
3. 在交易决策时，应该看到"从内存缓存读取价格"信息

**验证**：
```bash
# 检查Redis中的价格
redis-cli HGET price:binance:BTCUSDT price
redis-cli HGET price:binance:BTCUSDT ts
```

---

### 3. 测试开仓点验证

**步骤**：
1. 等待L1事件触发交易决策
2. 观察日志，应该看到：
   - "开仓点验证"信息
   - "风险回报比验证"信息
3. 如果价格在极值位置，应该看到：
   - "开仓点验证失败: 价格在区间高位/低位"
   - "风险回报比验证失败: 风险回报比过低"

---

### 4. 测试风控检查

**步骤**：
1. 确保已有多个仓位（测试最大仓位数量限制）
2. 等待新的L1事件触发
3. 观察日志，应该看到：
   - "风控拦截: 已达到最大仓位数量"
   - 或其他风控拦截原因

**验证**：
```bash
# 查看当前仓位数量
redis-cli SCARD trading:open_positions:binance
```

---

### 5. 测试仓位快照

**步骤**：
1. 启动WebSocket用户数据监听
2. 等待5分钟（默认快照间隔）
3. 观察日志，应该看到：
   - "仓位快照完成: 真实仓位=X, 记录仓位=Y, 清理=Z"

**验证**：
```bash
# 查看仓位快照前后的变化
redis-cli SMEMBERS trading:open_positions:binance
```

---

### 6. 测试实时仓位监控

**步骤**：
1. 启动仓位监控服务
2. 确保有已开仓位
3. 等待60秒（默认检查间隔）
4. 观察日志，应该看到：
   - "仓位正常"或"仓位风险警告"信息

- 文件：`agent_server/logs/trade_decision_YYYYMMDD.log`
- 内容：交易决策、去重检查、风控检查、开仓点验证

### 仓位监控日志
- 控制台输出
- 内容：仓位风险检查、风险警告

### 仓位快照日志
- 控制台输出（user_ws.py）
- 内容：快照完成、清理记录

## 常见问题

### Q1: 如何查看优化功能是否生效？

**A**: 查看日志文件，搜索关键词：
- "订单去重检查通过" - 交易去重
- "从内存缓存读取价格" - 价格缓存
- "开仓点验证" - 开仓点验证
- "风控拦截" - 风控检查
- "仓位快照完成" - 仓位快照
- "仓位风险警告" - 仓位监控

---

### Q2: 如何验证仓位快照是否工作？

**A**: 
1. 手动在Redis中添加一个不存在的交易对：
   ```bash
   redis-cli SADD trading:open_positions:binance FAKESYMBOL
   ```
2. 等待5分钟
3. 检查是否被清理：
   ```bash
   redis-cli SMEMBERS trading:open_positions:binance
   ```
4. FAKESYMBOL应该被移除

---

### Q3: 如何测试价格缓存？

**A**:
1. 启动WebSocket市场数据监听
2. 等待价格更新
3. 在交易决策日志中搜索"从内存缓存读取价格"
4. 如果看到这个信息，说明价格缓存工作正常
